Google Apps interacts with your Discord server through Discord's standard permission system. Getting permissions right is essential — grant too few and features stop working; leave things too open and members may access commands they shouldn't. This page explains every permission the bot needs, how to lock down individual commands, and how Discord's role hierarchy affects what the bot can actually do.

## Required Bot Permissions

When you invite Google Apps to your server, the bot requests the following permissions. Removing any of them will partially or fully disable the features that depend on them.

| Permission | Why It's Needed |
|---|---|
| **View Channels** | Required to read messages and respond to commands in any channel. |
| **Send Messages** | Allows the bot to post command responses, embeds, and notifications. |
| **Send Messages in Threads** | Ensures command responses work inside thread channels. |
| **Embed Links** | Required to display rich embeds for `/serverinfo`, `/userinfo`, polls, and mod-log entries. |
| **Attach Files** | Used to send images (e.g. `/avatar` full-resolution download). |
| **Read Message History** | Needed by `/clear` to find and bulk-delete messages. |
| **Add Reactions** | Allows the bot to add vote reactions to `/poll` messages. |
| **Manage Messages** | Required by `/clear` to delete other members' messages. |
| **Manage Channels** | Required by `/slowmode`, `/lock`, and `/unlock`. |
| **Manage Roles** | Required by `/role add` and `/role remove`. The bot can only manage roles below its own. |
| **Kick Members** | Required by `/kick`. |
| **Ban Members** | Required by `/ban`. |
| **Moderate Members** | Required by `/mute` (Discord Timeouts). |
| **Use Slash Commands** | Allows the bot to register and respond to `/` commands in the server. |

<Warning>
  Removing **Send Messages**, **Embed Links**, or **Use Slash Commands** will disable the bot's ability to respond to any command at all. If the bot suddenly stops responding, check that these three permissions are still granted — either server-wide or in each channel you expect it to work in.
</Warning>

## Command Permissions

By default, admin and moderation commands are only visible and usable by members with the **Administrator** or **Manage Server** permission. You can override this on a per-command basis directly inside Discord — no dashboard configuration needed.

**To restrict a command to specific roles:**

1. Open **Discord Server Settings**.
2. Navigate to **Integrations** → **Google Apps Bot**.
3. Click on any command in the list.
4. Under **Roles & Members**, toggle off **@everyone** and add the roles you want to grant access to.
5. Click **Save**.

Changes take effect immediately for all members.

<Note>
  Discord's integration settings let you restrict commands at the server level but cannot restrict them to a specific channel. Use Channel Overrides (below) to control per-channel access.
</Note>

## Channel Overrides

Channel overrides let you allow or deny bot commands in specific channels, regardless of a member's role permissions.

**To deny all bot commands in a channel:**

1. Open **Discord Server Settings → Integrations → Google Apps Bot**.
2. Click **Add Channel** under the channel override section.
3. Select the channel you want to restrict.
4. Toggle all commands (or individual ones) to **Denied** for that channel.

**Common use cases:**
- Restricting `/poll` to a dedicated `#polls` channel.
- Blocking all commands in `#announcements` so the bot only posts automated notifications there.
- Limiting `/warn` and `/ban` to a `#mod-commands` private channel.

## Role Hierarchy

Discord enforces a strict role hierarchy: a bot (or member) can only take actions on other members whose **highest role** is positioned **below** the bot's own highest role in the server's role list.

This means:

- The bot **cannot** kick, ban, mute, or assign roles to members whose highest role is equal to or above the bot's role.
- The bot **cannot** manage a role that is positioned above its own highest role.
- Server owners are always exempt from bot actions — the bot can never take moderation action against the server owner.

**Best practice:** Place the Google Apps bot role as high as possible in your role list — ideally just below your own admin role — so it can act on all regular member roles without restriction.

<Warning>
  If the bot's role is placed below your moderator or member roles, commands like `/kick`, `/ban`, `/mute`, and `/role` will silently fail when targeting members with those roles. Always verify role order after inviting the bot or reorganizing your role list.
</Warning>
