Google Apps' logging system gives server administrators complete visibility into everything happening on their server. Every significant event — from deleted messages to role changes and voice activity — is captured and posted to a configurable log channel in real time. This makes it easy to investigate incidents, audit moderator actions, and maintain an accurate record of server activity over time.

<Note>
  For logging to function correctly, the Google Apps bot requires the **Read Message History** and **View Audit Log** permissions on your server. Without these, certain event types — particularly moderation actions performed by other bots or directly by server admins — will not be captured.
</Note>

## Log Channels

You can direct different categories of logs to different channels, keeping your audit trail organized and easy to search. For example, you might send moderation events to a private `#mod-logs` channel visible only to your staff, while message events go to a `#message-logs` channel for reference.

To configure log channels:

1. Navigate to **Logging → Log Channels** in the Google Apps dashboard.
2. Click **Add Log Channel**.
3. Select the Discord channel from the dropdown.
4. Choose one or more **event categories** to route to that channel.
5. Click **Save**.

You can create multiple log channel entries and assign overlapping categories if needed. A single event can be delivered to more than one channel.

## Logged Events

Google Apps tracks a broad range of server events out of the box. The table below lists all supported event types and what information is included in each log entry.

| Event | Trigger | Details Logged |
|---|---|---|
| **Message Deleted** | A message is removed by the author or a moderator | Author, channel, message content, deleting user (if different) |
| **Message Edited** | A member edits a previously sent message | Author, channel, original content, new content, timestamp |
| **Member Join** | A new member enters the server | Username, user ID, account creation date, invite used |
| **Member Leave** | A member leaves or is removed from the server | Username, user ID, roles held at time of departure |
| **Member Banned** | A member is banned by a moderator | Target user, banning moderator, reason provided |
| **Member Kicked** | A member is kicked by a moderator | Target user, kicking moderator, reason provided |
| **Role Changes** | A role is assigned to or removed from a member | Target user, role affected, responsible moderator or bot |
| **Channel Changes** | A channel is created, deleted, or its settings are modified | Channel name, change type, responsible administrator |
| **Voice Activity** | A member joins, leaves, or moves between voice channels | Member name, origin channel, destination channel, timestamp |

## Log Filters

If your server is large or active, you may not need every event type logged to every channel. Log filters let you enable or disable individual event types per log channel, so you only see what's relevant.

To adjust filters:

1. Go to **Logging → Log Channels** and click the **Edit** icon next to a log channel.
2. Under **Event Filters**, toggle each event type on or off.
3. Click **Save Changes**.

Changes take effect immediately — no bot restart required. You can return to this panel at any time to adjust the filter configuration as your server's needs evolve.

## Log Retention

Log entries are retained for **90 days** by default. After this period, entries are automatically purged from the Google Apps dashboard. Discord's own channel history is subject to Discord's retention policies and is not affected by Google Apps' purge schedule.

If your server requires longer retention, you can upgrade to a plan that supports extended log storage of up to **365 days**. Retention settings are available under **Logging → Retention** in the dashboard.

## Exporting Logs

You can export a full or filtered log history as a CSV file directly from the dashboard. This is useful for compliance purposes, incident reports, or offline archiving.

To export logs:

1. Navigate to **Logging → Export** in the dashboard.
2. Set a **date range** for the export window.
3. Optionally filter by **event type**, **channel**, or **user**.
4. Click **Export as CSV**.
5. The file will be generated and downloaded automatically. Large exports may take a few seconds to prepare.

Exported files include all logged fields for each event, including timestamps in UTC ISO 8601 format, making them straightforward to import into spreadsheet tools or data pipelines.
